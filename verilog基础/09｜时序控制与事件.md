# 时序控制与事件

返回 [[00｜Verilog基础·学习地图]] · 前篇 [[08｜过程赋值与调度]] · 后篇 [[10｜条件分支与循环]]

## 一、三类等待

| 形式 | 等待对象 | 例子 |
|---|---|---|
| `#delay` | 经过指定时间 | `#10;` |
| `@(event)` | 后续发生一次指定事件 | `@(posedge clk);` |
| `wait(expr)` | 条件表达式为真 | `wait(ready);` |

等待只暂停当前过程，其他过程继续运行。时间单位与精度由 [[05｜编译指令与宏#时间单位与精度|timescale]] 等设置决定。

## 二、语句延时与赋值内延时

设过程在 t=0 执行到以下语句，随后 b 在 t=2 由 0 变成 1：

| 写法 | b 在何时取样 | a 何时更新 | 后续语句何时能执行 |
|---|---|---|---|
| `#5 a = b;` | t=5 | t=5 | t=5 赋值后 |
| `a = #5 b;` | t=0 | t=5 | t=5 赋值后 |
| `a <= #5 b;` | t=0 | t=5 的 NBA | t=0 继续 |
| `#5 a <= b;` | t=5 | t=5 的 NBA | t=5 安排更新后 |

因此前两种虽在同一时刻更新，写入的值可能不同。第二种先保存右值，再阻塞等待；第三种先保存右值并安排未来更新，当前过程不等待。

```verilog
// 一个过程内片段。
#10;
a = b;
```

与 `#10 a = b;` 在这段独立顺序执行场景中具有相同取样时机。分号在这里构成空语句：先等待，再执行下一句。连续赋值的 `assign #10` 则属于另一种模型，见 [[06｜连续赋值与三态驱动]]。

## 三、边沿事件与电平条件

```verilog
@(posedge clk);          // 等待下一次上升沿
@(negedge rst_n);        // 等待下一次下降沿
@(a or b);              // 等待 a 或 b 的变化
wait (ready == 1'b1);    // 已为真则立刻继续，否则等待
```

`@(posedge clk)` 不会因为 clk 此刻已为 1 就立刻继续，它等待后续边沿；`wait(ready)` 则先看当前电平条件。

四态仿真中边沿不仅包含 0→1、1→0：例如 0→x/z、x/z→1 也可构成 posedge；反向的相应变化可构成 negedge。x→z 并不构成这类边沿。复位和时钟初始化时要留意未知态触发。

## 四、组合敏感列表

```verilog
always @* begin
    s = a ? b + c : (d ? e + f : m);
end
```

`@*` 自动考虑该过程读取的信号，例如条件中的 a、d，以及分支表达式里的 b、c、e、f、m。这里的“输入”是过程读取的数据依赖，不限于模块声明的 input 端口；也可能是内部 wire/reg。

`@*` 省去手写敏感列表，但不自动补齐组合过程的赋值分支，也不自动消除多个过程之间的竞争。SV 的 `always_comb` 另有起始执行与单一写入等规则，不与 `always @*` 完全等同。

> [!warning] 旧片段中的 assign 要更正
> `always @* begin assign s = ...; end` 中的 assign 是 [[11｜过程连续赋值与强制驱动|过程连续赋值]]，不是普通组合过程推荐写法。若 s 是 reg，组合过程内写 `s = ...;`；若 s 是 wire，把 `assign s = ...;` 放到模块级。

## 五、命名事件

```verilog
event start_receiving;

always @(posedge clk_samp) begin
    -> start_receiving;
end

always @(start_receiving) begin
    data_buf = {data_if[0], data_if[1]};
end
```

`event` 声明同步事件，`->` 触发，`@` 等待。该示例中 data_if[0] 放在拼接结果的高位部分。

命名事件不保存一份“已触发”状态；触发发生时若监听过程尚未进入等待，可能错过事件。同一时刻的启动先后尤其需要考虑。它主要用于仿真同步，普通 RTL 中通常直接用时钟与握手信号表达电路。

## 六、时间查看与停止

| 系统任务/函数 | 用途 |
|---|---|
| `$time` | 返回按当前时间单位表示的整数仿真时间 |
| `$realtime` | 返回实数形式的仿真时间 |
| `$display` | 执行到语句时打印 |
| `$monitor` | 相关实参变化时安排监视输出 |
| `$strobe` | 当前时刻后面的观察阶段打印 |
| `$finish` | 结束仿真 |

`%t` 的显示还受时间格式设置影响，不能只看终端数字就断定 `timescale` 错误。

## 七、复习检查

- `#5 a=b` 与 `a=#5 b` 的差别在右侧取样时刻。
- ready 已为 1 时，wait 可立即通过，边沿等待仍需后续事件。
- `#0` 让出执行机会但不推进物理时间，也不保证 NBA 已完成。
