# 过程连续赋值与强制驱动

返回 [[00｜Verilog基础·学习地图]] · 前篇 [[10｜条件分支与循环]] · 后篇 [[12｜模块端口与例化]]

## 一、三个名称相近的机制

| 机制 | 放置位置 | 主要对象 | 结束方式 |
|---|---|---|---|
| 模块级 `assign` | 模块内部、过程之外 | 传统 Verilog 线网 | 作为结构持续存在 |
| `assign/deassign` | 过程内部 | 传统 Verilog reg 类变量 | `deassign` 撤去过程连续赋值 |
| `force/release` | 过程内部 | 线网或变量 | `release` 解除强制 |

后两组主要用于理解旧模型和仿真控制；常规组合 RTL 优先使用模块级 assign 或完整组合过程。不能仅看 assign 单词就认定是同一种赋值。

## 二、assign/deassign

```verilog
// 仿真示例片段；q、d 声明为 reg。
initial begin
    d = 1'b0;
    q = 1'b0;
    assign q = d;
    #5 d = 1'b1;  // 激活期间 q 跟随 d
    #5 deassign q;
    #5 d = 1'b0;  // q 不再跟随 d，暂保留先前的 1
    #5 q = 1'b0;  // 普通过程赋值重新更新 q
end
```

过程执行到 assign 时才激活这条关系；激活后优先于 q 的普通过程赋值，直到撤去。deassign 不会自动把变量还原成激活前的旧值，也不会重新执行曾被覆盖的赋值。

具体工具可能对非常量右侧表达式的过程连续赋值给出支持限制或警告。若要用它复现实验，应核对本机工具行为；不要拿它取代正常 RTL。

## 三、force/release

force 用于暂时覆盖目标，例如 TB 故障注入、复位模拟或调试内部节点：

```verilog
// TB 片段，dut.internal_signal 是已存在的层次路径。
initial begin
    #10 force dut.internal_signal = 1'b0;
    #20 release dut.internal_signal;
end
```

不同目标在 release 后的行为不同：

| 目标 | release 后 |
|---|---|
| 线网 | 由原有驱动重新决定解析值 |
| 普通过程变量 | 保留被强制后的值，直到后续有效过程赋值更新 |
| 还有有效过程连续赋值的变量 | 需要进一步考虑仍存在的赋值来源 |

force 不是给目标再加一个普通强度驱动，也不能只按 wire 的电气强度解析表分析。对层次端口使用 force 时还可能涉及端口合并的影响，应明确实际目标。

## 四、与组合过程的正确区分

```verilog
// 推荐的传统 Verilog 组合过程。
always @* begin
    s = a ? b : c;
end
```

此处 s 为 reg，不写 `assign s = ...;`。若要用模块级 assign，则 s 声明为 wire，并移除该组合过程。这能让驱动来源和电路意图保持清晰。

## 五、复习检查

- deassign/release 都不是“恢复历史快照”。
- 解除 force 后，线网与普通变量的恢复时机不同。
- 工程里读到过程内部的 assign，要识别它是特殊机制，不能照抄到普通组合 RTL。
