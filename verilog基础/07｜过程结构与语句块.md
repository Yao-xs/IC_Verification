# 过程结构与语句块

返回 [[00｜Verilog基础·学习地图]] · 前篇 [[06｜连续赋值与三态驱动]] · 后篇 [[08｜过程赋值与调度]]

## 一、initial 与 always

| 结构 | 执行方式 | 常见用途 |
|---|---|---|
| `initial` | 在仿真开始启动一次，执行完即结束 | 初始化、激励、结束控制 |
| `always` | 执行主体后不断重复 | 组合过程、时钟过程、TB 时钟 |

“initial 只执行一次”指整个过程启动一次，其内部可以包含循环并持续很长时间。多个 initial/always 并发执行，彼此没有文件顺序保证。

```verilog
reg clk;
initial clk = 1'b0;
always #5 clk = ~clk;  // 仿真时钟；周期为 10 个时间单位
```

如果 `always` 主体没有任何事件或延时等待，就可能形成零时间死循环：

```verilog
// 错误建模示意，勿运行：always begin a = ~a; end
```

## 二、begin/end：过程内顺序执行

```verilog
initial begin
    #5 a = 1'b1;
    #5 b = 1'b1;
end
```

该过程从 t=0 开始，a 在 t=5 更新，b 在 t=10 更新。延时相对于该过程当前时间累计。

没有 `begin/end` 时，if、循环等通常只控制紧随其后的一条语句。命名块写为：

```verilog
initial begin : stimulus
    integer i;
    i = 0;
    repeat (4) begin
        #10 i = i + 1;
    end
end
```

命名块带作用域，可用 `stimulus.i` 在适当层次访问该变量。传统 Verilog 中块内声明放在语句前；很多旧式工具需要命名块才能使用这类局部声明。

## 三、fork/join：过程内建立并发分支

```verilog
initial fork
    #5 a = 1'b1;
    #5 b = 1'b1;
join
```

两个分支都相对于进入 fork 的时间等待，a、b 都在 t=5 更新。父过程等到所有分支完成后才继续。

若某条分支需要多句顺序执行，将它放进 begin/end：

```verilog
initial begin
    fork
        begin
            #5 a = 1'b1;
            #5 a = 1'b0;
        end
        #7 b = 1'b1;
    join
    // 到 t=10 两条分支才都结束。
end
```

不要只按物理行数理解分支数量。`fork/join` 常用于仿真并发激励，不是普通 RTL 的默认写法。

## 四、结合旧提问比较三种情况

| 代码形态 | a 的更新 | b 的更新 | 决定因素 |
|---|---|---|---|
| begin 内连续两句 `#5 a=...; #5 b=...;` | t=5 | t=10 | 一个过程内阻塞等待累积 |
| fork 中两条 `#5 ... = ...;` | t=5 活动事件处理 | t=5 活动事件处理 | 两条分支同时开始 |
| fork 中两条 `#5 ... <= ...;` | t=5 NBA 更新 | t=5 NBA 更新 | 并发分支 + 非阻塞调度 |

并发来自 fork 或独立过程，`<=` 改变的是赋值更新调度。不能把“用了非阻塞”直接解释成“这两句自动位于不同线程”。

## 五、块退出与仿真退出

- 命名块可用 `disable 块名;` 终止相应块，常见于旧式 TB 控制。
- `disable` 的对象与层次需明确；不要当作通用软件 return/break 随意使用。
- `$finish` 结束整个仿真；`$stop` 通常进入暂停/交互状态。
- SystemVerilog 的 `join_any/join_none`、`break/continue` 属于后续语言扩展，使用时明确启用模式。

## 六、复习检查

- `begin/end` 控制所在过程内部顺序，不决定其他 initial 的执行次序。
- fork 中某个分支含 forever 且不退出时，普通 join 就不会返回。
- 声明了 `reg clk` 而未初始化，`~clk` 可能一直为 x，不能生成干净时钟。
