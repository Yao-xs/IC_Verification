# 设计方法与语言骨架

返回 [[00｜Verilog基础·学习地图]] · 前篇 [[01｜Icarus环境与仿真流程]] · 后篇 [[03｜数值表示与数据类型]]

## 一、从需求得到电路描述

Verilog 是硬件描述语言。写代码时同时考虑信号连接、运算关系、状态保存和事件发生时刻。

推荐按以下顺序设计：

1. **定义接口**：输入输出方向、位宽、有效电平、时钟复位。
2. **列出行为**：真值表、数据流、状态转移、边界条件。
3. **划分电路**：哪些是组合逻辑，哪些需要在时钟沿保存状态。
4. **选择描述方式**：连续赋值、组合过程、时序过程或子模块连接。
5. **设计检查**：正常值、边界、复位、无效输入、冲突等。

## 二、常见建模方式

| 方式 | 常用结构 | 现有例子 |
|---|---|---|
| 数据流描述 | `assign` 与表达式 | 全加器的异或与进位逻辑 |
| 行为描述 | `always`、`if`、`case` | 四选一选择器 |
| 结构描述 | 子模块/门原语例化 | 四个一位加法器组成四位加法器 |

同一设计可以组合使用这三种方式。对功能等价的写法，还要比较可读性、参数扩展、位宽以及综合结果；不能只凭代码行数判断电路速度或面积。

## 三、模块的语言骨架

完整的二选一组合模块：

```verilog
module mux2 (
    input  wire a,
    input  wire b,
    input  wire sel,
    output wire y
);
    assign y = sel ? b : a;
endmodule
```

- `module ... endmodule` 定义模块类型。
- 端口说明模块边界；模块内部可以有声明、连续赋值、过程和子模块实例。
- 普通声明与赋值以分号结束；`begin/end`、`module/endmodule` 等配对结构按语法闭合。
- 关键字与标识符区分大小写：`Sum` 与 `sum` 是不同名字。
- 单行注释使用 `//`，多行注释使用 `/* ... */`。
- 文件名与模块名可以不同，但同名便于查找和库搜索。

## 四、组合与时序的基本模板

组合过程片段，`y` 声明为 `reg`：

```verilog
always @* begin
    y = a;
    if (sel)
        y = b;
end
```

默认赋值使每条路径都定义 `y`。如果输入变化时某条路径没有赋值，旧值需要保留，可能推断锁存器。

时序过程片段，`q` 声明为 `reg`：

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 1'b0;
    else if (enable)
        q <= d;
end
```

这里的状态更新由边沿触发。未使能时保持原值是时序设计的正常行为。异步复位有效电平为低；同步复位的敏感列表则只包含时钟边沿。

> [!warning] “少写 else”要按电路类型判断
> 组合过程遗漏输出赋值可能产生锁存器；时钟过程遗漏使能分支的 else 通常表示寄存器保持。两者不能用同一条机械规则判断。

## 五、并发是模块级的基本特征

多个 `assign`、多个 `initial` 和多个 `always` 各自并发存在。`begin/end` 只规定所在过程内部的执行顺序，不让整个模块变成一个顺序程序。

```verilog
// 模块内片段：两条连接同时存在。
assign t = a & b;
assign y = t | c;
```

上述关系会通过仿真事件传播，硬件中则是组合路径；不能解释成“只执行第一行一次，再执行第二行一次”。

## 六、设计与测试分工

| RTL 设计 | Testbench |
|---|---|
| 说明电路应如何响应输入 | 主动产生输入与时钟 |
| 描述组合连接和状态更新 | 使用 `#`、`initial`、打印、波形及检查 |
| 关注可综合行为与接口约束 | 关注功能是否符合预期 |

`initial` 在某些 FPGA 流程可用于上电初始化，但不能据此推导 ASIC 也有同样硬件。`#10` 在普通 RTL 综合中通常不能实现“等待 10 ns 的电路”。

## 七、复习检查

- 设计一个选择器时，先写真值表和端口，再选择 `assign` 或组合过程。
- 判断是否保存状态，要看触发方式和赋值是否完整，不能只看 `reg`。
- 仅修改 TB 的激励，不会自动改变 DUT 的功能定义。
