## 二、四位全加器

### 结构与功能

一位全加器满足：

```verilog
assign Sum  = A ^ B ^ Cin;
assign Cout = (A & B) | (A & Cin) | (B & Cin);
```

四位版本把每一级 Cout 接到下一级 Cin：

```text
Cin → bit0 → bit1 → bit2 → bit3 → Co
        ↓      ↓      ↓      ↓
       So[0]  So[1]  So[2]  So[3]
```

最终比较对象是 `{Co, So}`，共 5 位。A=15、B=15、Cin=1 时，结果为 31，即 `5'b11111`。

### 历史问题与固定检查

| 历史问题 | 根因 | 检查方法 |
|---|---|---|
| 4000 多条层次展开错误 | 四位模块内部又例化四位模块 | 每一级应例化 full_adder1 |
| 端口名不匹配 | 把一个模块的端口名用于另一类型 | 对照子模块声明检查 `.端口名` |
| 第 3 位无驱动 | 第 0 位单列，但循环只到 i<3 | 其余位应使用 i=1、i<4 |
| 进位丢失风险 | 参考值或目标宽度不足 | 比较与存储都保留 5 位 |

TB 的三层循环共 `16 × 16 × 2 = 512` 组。施加输入后等待 `#1` 再比较，给组合传播留出仿真时间；这不是测量真实门延时。

## 三、四选一选择器

输入为四组 2 位数据 p0～p3，由 2 位 sel 选择，输出 2 位 sout。已有 RTL 用组合 if 链更新 reg sout_t，再连续赋值给 wire sout。

对确定的 00/01/10/11 选择码，数据通路有完整赋值；未知 sel 可能落入最终 else 选择 p3，见 [[10｜条件分支与循环]]。

当前 TB 的问题：

```verilog
rgb(0, 0, 0);
```

这是未定义任务调用，不能当作 Verilog 的通用打印或控制语句。该语句导致现有 TB 无法完成展开。本次只记录问题，不修改原始学习代码。

此外，`if ($time >= 1000) $finish;` 若只在 t=0 执行一次，不能自动变成“到 1000 时触发”。更清楚的 TB 结束片段是：

```verilog
initial begin
    #1000;
    $finish;
end
```

后续可为四种 sel 都加入自动输出比较，并说明未知选择码的处理策略。

## 四、PAD 与三态驱动

### 端口与方向

| 信号 | 含义 |
|---|---|
| DIN | 内部准备驱动到引脚的数据 |
| OEN | 0 为输出模式，1 为输入模式 |
| PULL[1:0] | 第 1 位使能附加驱动，第 0 位决定附加电平 |
| PAD | inout 线网，由各驱动共同决定 |
| DOUT | 输入模式读取 PAD，输出模式在当前模型中置 z |

历史 input coerced to inout 警告已通过把 PAD 改为 inout 修正。警告行号可能位于 TB 的连接处，真正错误声明则在 DUT。

### 原 TB 的稳定后预期

| 时间 | 主要变化 | PAD | DOUT |
|---|---|---|---|
| 0 ns 初始事件稳定后 | OEN=1，外部 z，PULL=10 | 0 | 0 |
| 20 ns | PULL=11 | 1 | 1 |
| 40 ns | PULL=00，各驱动释放 | z | z |
| 60 ns | PAD_REG=0 | 0 | 0 |
| 80 ns | PAD_REG=1 | 1 | 1 |
| 110 ns | OEN=0，DIN=z | z | z |
| 125 ns | DIN=0 | 0 | z |
| 140 ns | DIN=1 | 1 | z |
| 1000 ns | 原 TB 的 finish 过程 | 结束 | 结束 |

这是依据源代码累积延时得到的时序表。另用 9 项补充检查核验了相应功能与同强度相反驱动产生 x 的情况；原 TB 本身仍主要是激励和波形记录，没有这些自动断言。

补充检查中特别显式产生 OEN 的变化，避免把声明时初始化后的稳定输入误当成 `always @*` 必然在 t=0 自动执行。SV `always_comb` 才另有 t=0 执行规则。

## 五、runoob 中的循环与竞争

`runoob.v` 在命名块 runoob 内每隔 10 个时间单位增加 i，另一个过程每隔 10 个时间单位检查 `runoob.i == 100`。

两个过程都在 t=1000 附近访问 i，且写入使用阻塞赋值，检查过程在同一时刻可能先读后写，也可能先写后读。因此不要把终止时间固定记成一定是 1000。更直接的教学结束过程可写为：

```verilog
initial begin
    wait (runoob.i == 100);
    $finish;
end
```

它利用条件等待，而不是用另一个同相位轮询过程竞争读取。具体同步设计仍需明确变量由谁更新、何时采样。

## 六、旧笔记中应统一修正的表述

| 容易误记的说法 | 整理后的准确说法 |
|---|---|
| reg 就是硬件寄存器 | reg 是变量类别，电路由过程语义决定 |
| 非阻塞会自动避免所有竞争 | NBA 解决部分更新顺序问题，多过程同写与 TB 采样仍需设计 |
| 三种连续赋值延时永远完全等价 | 简单单驱动情形可能相同，赋值延时与线网延时作用位置不同 |
| 只有被例化的模块能仿真 | 模块也可作为编译器选定的根模块 |
| -o 会自动加 .vvp | 输出名完全按参数写出 |
| sim.f 可以直接删除 | 必须先检查任务和脚本是否仍引用它 |
| 一个有波形的 TB 就验证通过 | 应有明确预期和比较，波形生成只证明运行过 |
| 算术右移等于带符号除法 | 对负奇数的取整结果可能不同 |
