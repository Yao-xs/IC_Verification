# 连续赋值与三态驱动

返回 [[00｜Verilog基础·学习地图]] · 前篇 [[05｜编译指令与宏]] · 后篇 [[07｜过程结构与语句块]]

## 一、连续赋值是一条持续驱动关系

```verilog
wire y;
assign y = a & b;
```

这条模块级语句持续将表达式的结果驱动到 y。右侧变化会引起重新求值与更新，不需要等待过程再次走到某行。传统 Verilog 中左值应是线网、线网位选/片选或它们的拼接。

另一种写法是线网声明赋值：

```verilog
wire y = a & b;
```

这里仍是连续关系。`reg y = 0;` 则是变量声明初始化，不能理解为“y 永远跟随 0”。

## 二、同一种组合功能的两种描述

```verilog
// 写法 A：输出为 wire。
assign y = sel ? p1 : p0;
```

```verilog
// 写法 B：输出为 reg。
always @* begin
    if (sel)
        y = p1;
    else
        y = p0;
end
```

选择其中一种实现，不要让两种写法同时驱动同一普通输出。过程中的赋值详见 [[08｜过程赋值与调度]]。

## 三、连续赋值延时

下列是三种独立仿真模型，不能并列作为同一 Z 的三个驱动：

```verilog
wire Z;
assign #10 Z = A & B;
```

```verilog
wire #10 Z = A & B;
```

```verilog
wire #10 Z;
assign Z = A & B;
```

前两种在此单驱动例子中描述带延时的连续赋值；第三种是线网延时，作用于该线网上的驱动更新。单驱动、相同延时下可能观察到相同波形，但两者作用位置不同，多驱动和多级延时情形不能笼统等同。

连续赋值延时具有惯性行为，较窄脉冲可能被滤除。它不等同于“把每一个变化都无条件推迟再完整传过去”。普通 RTL 中也不靠 `#10` 实现真实电路的 10 ns 等待。

## 四、三态输出与驱动解析

```verilog
assign PAD = OEN ? 1'bz : DIN;
```

OEN=0 时内部驱动 DIN；OEN=1 时内部释放 PAD。OEN 是低有效输出使能，不能只看名字就认为 1 表示输出。

在忽略更细驱动强度差异、两个有效驱动强度相同的情况下：

| 驱动 A | 驱动 B | 线网结果 |
|---|---|---|
| z | z | z |
| 0 | z | 0 |
| 1 | z | 1 |
| 0 | 0 | 0 |
| 1 | 1 | 1 |
| 0 | 1 | x |

`z` 是该驱动不提供确定电平；多个驱动合在一起才得到线网的解析值。三态通常用于芯片 I/O 或特定总线建模；FPGA 内部三态常会被综合成选择器，需看目标器件。

## 五、现有 PAD 模型中的三条驱动

1. DUT：由 DIN/OEN 控制的输出。
2. TB：由 PAD_REG/OEN 控制的外部输入。
3. DUT：由 `bufif1` 控制的附加驱动。

```verilog
bufif1 puller (PAD, PULL[0], PULL[1]);
```

门原语端口顺序为输出、数据、使能。`PULL=10` 驱动 0，`PULL=11` 驱动 1，`PULL[1]=0` 则释放。

> [!warning] 名为 puller 不代表弱上拉
> 当前 `bufif1` 使用默认强驱动。若同强度的外部驱动给出相反值，会出现 x。若要模拟弱上下拉，应明确选择适当的 pullup/pulldown 原语或强度模型，并重新验证行为。

## 六、复习检查

- PAD 是双向节点，应声明 `inout wire`，不应声明为纯 input。
- `wire` 能解析多驱动，不代表任意多驱动设计都合理。
- 外部信号未驱动时不应随便用 0 代替 z，否则会改变总线行为。
