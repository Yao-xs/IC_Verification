# 过程赋值与调度

返回 [[00｜Verilog基础·学习地图]] · 前篇 [[07｜过程结构与语句块]] · 后篇 [[09｜时序控制与事件]]

## 一、过程赋值的基本对象

过程赋值写在 initial/always 或任务等过程中，传统 Verilog 左值使用 reg、integer 等变量。执行流走到语句时才触发赋值操作。

| 写法 | 求右值 | 更新左值 | 当前过程是否等待更新 |
|---|---|---|---|
| `a = b;` | 执行到语句时 | 此语句完成前 | 是，随后再执行下一句 |
| `a <= b;` | 执行到语句时 | 安排在 NBA 阶段 | 不等待左值更新 |

这里讨论无显式延时的基本形式。带延时的行为需进一步区分 [[09｜时序控制与事件#语句延时与赋值内延时]]。

## 二、阻塞赋值：后句看得到前句新值

```verilog
// 过程内片段；开始时 a=1、b=0。
a = b;  // a 立即成为 0
b = a;  // 读取刚更新的 a，b 仍为 0
```

常用于组合过程的中间计算：

```verilog
always @* begin
    temp = a & b;
    y = temp | c;
end
```

temp、y 是 reg。执行顺序反映了组合计算的依赖关系。

## 三、非阻塞赋值：先取样，后更新

```verilog
// 同一过程内片段；开始时 a=1、b=0。
a <= b;  // 安排 a=0
b <= a;  // 此刻 a 尚未更新，安排 b=1
```

在这组 NBA 完成后，a=0、b=1。非阻塞不是“等一整个时钟周期”，它通常在**当前仿真时刻**的 NBA 事件处理中更新。

两级寄存器片段：

```verilog
always @(posedge clk) begin
    q1 <= d;
    q2 <= q1;
end
```

两句都在该上升沿取右值，q2 获得的是沿前的 q1，形成流水寄存器行为。若改用阻塞，q2 可能直接读到刚写入 q1 的 d，语义改变。

## 四、常用设计纪律

1. 完整组合过程通常使用 `=`。
2. 描述时钟沿触发的状态更新通常使用 `<=`。
3. 同一个普通 RTL 变量由一个过程负责，不混合多个驱动者。
4. 同一变量不混用阻塞与非阻塞写入。
5. TB 施加输入尽量避开 DUT 采样沿，输出检查应在预期更新之后。

这些是让仿真与电路意图清晰一致的工程约定，不能替代对实际调度的分析。

## 五、非阻塞赋值不能自动消除所有竞争

竞争指同一仿真时刻的结果依赖于没有规定的事件执行先后。例如：

```verilog
// 两个独立过程写 q，属于不良设计。
always @(posedge clk) q <= a;
always @(posedge clk) q <= b;
```

同样，TB 在 posedge 用阻塞赋值改变输入，而 DUT 同时读取该输入，也可能读到新值或旧值。NBA 后才更新的输出若在活动事件阶段检查，可能看到旧值。

简化记忆：先执行当前活动事件，再处理 `#0` 等非活动事件，随后处理 NBA；观察类系统任务还有自己的处理区域。完整 SystemVerilog 调度更细，不能用这一简化顺序覆盖所有验证结构。

> [!tip] `$display` 与 `$strobe`
> 同一时刻执行 `$display` 可能看到 NBA 前的值；`$strobe` 在该时刻后面的观察阶段输出最终值。`#0` 并不保证已经跨过 NBA。

## 六、现有计数器为什么用 #1 检查

```verilog
@(posedge clk);
#1 check_count(expected);
```

这使 TB 在本例的时钟沿后 1 ns 观察，避开该沿的 NBA 更新。它是当前 10 ns 周期示例中的简单采样安排，并非任意设计通用的验证同步协议。更复杂 SV 验证可使用 clocking block 等机制。

## 七、复习检查

- 非阻塞赋值何时读取右侧？执行到语句时。
- 同一块中两句 `<=` 是否让下一句读取上一句的新左值？通常不会。
- 两个过程都用 `<=` 写同一变量是否安全？不是，仍有竞争与多驱动问题。
