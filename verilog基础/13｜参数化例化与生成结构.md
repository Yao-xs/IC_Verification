# 参数化例化与生成结构

返回 [[00｜Verilog基础·学习地图]] · 前篇 [[12｜模块端口与例化]] · 后篇 [[14｜学习实验与易错点复盘]]

## 一、parameter 是实例级配置

参数在展开阶段确定，可以决定位宽、深度、常量或结构。它不是运行时可随意改变的输入信号。

```verilog
module adder_param #(
    parameter WIDTH = 8
)(
    input  wire [WIDTH-1:0] a,
    input  wire [WIDTH-1:0] b,
    output wire [WIDTH:0] sum
);
    assign sum = {1'b0, a} + {1'b0, b};
endmodule
```

输出比输入宽一位，明确保留进位。若故意只要低 WIDTH 位，应显式说明截断策略。

## 二、带参数的命名例化

```verilog
// 父模块内片段；信号位宽应与各实例匹配。
adder_param #(.WIDTH(4)) u_add4 (
    .a(a4), .b(b4), .sum(sum5)
);
adder_param #(.WIDTH(16)) u_add16 (
    .a(a16), .b(b16), .sum(sum17)
);
```

`#(...)` 连接参数，后面的 `(...)` 连接端口。同一模块定义可以同时生成不同配置的实例，彼此互不覆盖。

位置参数覆盖如 `#(16)` 依赖参数声明顺序，维护时更容易误用；优先命名覆盖。旧式 `defparam` 通过层次路径改参数，不利于局部理解，通常不作为新代码的首选。

## 三、parameter、localparam 与宏

| 机制 | 生效方式 | 能否按实例覆盖 | 典型用途 |
|---|---|---|---|
| `parameter` | 展开阶段常量 | 可以 | 模块公开配置 |
| `localparam` | 模块内固定常量 | 不可直接外部覆盖 | 状态编码、派生宽度 |
| 宏 `` `define `` | 预处理文本替换 | 不是独立实例配置 | 条件编译、共同头文件 |

localparam 可以由 parameter 推导，因此上层改 parameter 后，派生 localparam 也可随之变化；“不可覆盖”不表示永远只能写死一个字面数字。

参数需有合法范围。例如 WIDTH 应至少为 1，否则 `[WIDTH-1:0]` 不会自然变成安全的“零位信号”。参数化模块必须说明并检查支持的边界。

## 四、generate 在展开阶段创建结构

用 N 个一位全加器组成参数化进位链，完整模块示例：

```verilog
module ripple_adder #(
    parameter WIDTH = 4
)(
    input  wire [WIDTH-1:0] A,
    input  wire [WIDTH-1:0] B,
    input  wire Cin,
    output wire [WIDTH-1:0] So,
    output wire Co
);
    wire [WIDTH:0] carry;
    assign carry[0] = Cin;
    assign Co = carry[WIDTH];

    genvar i;
    generate
        for (i = 0; i < WIDTH; i = i + 1) begin : gen_adders
            full_adder1 u_fa (
                .A(A[i]), .B(B[i]), .Cin(carry[i]),
                .Sum(So[i]), .Cout(carry[i+1])
            );
        end
    endgenerate
endmodule
```

它依赖 [[12｜模块端口与例化]] 中的 full_adder1 定义，WIDTH 约束为正整数。genvar 只参与展开，不是运行中的计数寄存器。

WIDTH=4 时，生成 4 个实际实例和 5 个进位节点，而不是一个实例“重复调用四次”。命名生成块使层次路径稳定、可读。

## 五、条件生成与运行时选择

```verilog
// 模块内结构片段。
generate
    if (USE_FEATURE) begin : gen_feature
        // 此处放选定配置才存在的连线或实例。
    end
endgenerate
```

USE_FEATURE 应是展开时已知的常量配置；输入信号 sel 的运行时选择则用 assign、组合 if/case 等。条件生成不会在每个时钟沿动态添加或删除硬件。

## 六、与当前四位全加器的联系

当前工作区把第 0 位单独例化为 FA0，再通过 `for(i=1; i<4; i=i+1)` 生成其余三位。上面的通用版本把 Cin 直接接到 carry[0]，因此可统一从 0 循环到 WIDTH-1。

两种结构均可形成进位链。关键是每一位 Sum 都有驱动，最后一级进位确实连接 Co，且每一级例化的是 full_adder1 而非递归的 full_adder4。

## 七、复习检查

- 参数影响实例的固定配置，输入影响电路的运行值。
- WIDTH 改变后，TB 的激励范围、参考值宽度和循环边界也要同步检查。
- 一个 generate for 与一个过程 for 是否发生在同一阶段？不是。
